# Routing support tickets

You'll see one customer support ticket at a time. Pick the one category that
says which team should handle it. Every ticket gets exactly one category, and
selecting it moves on to the next ticket.

## Categories

| Category | Pick it when the ticket is about |
|---|---|
| `BILLING` | Charges, invoices, refunds, renewals, plan changes |
| `BUG_REPORT` | Something broken for one feature, user or workflow |
| `HOW_TO` | How to use or configure something that already exists |
| `FEATURE_REQUEST` | New functionality, or a change to how something works |
| `OUTAGE` | Something down for everyone, a whole office or the workspace |
| `ACCOUNT_ACCESS` | Signing in, SSO, credentials, invitations, lockouts |

## Telling the close ones apart

- **`BUG_REPORT` or `OUTAGE`?** Ask how many people are affected. One feature
  failing for one team is a bug. "All users", "the whole office" or
  "everything returns" is an outage. This is the pair that costs the most when
  it's wrong, so take a second look.
- **`BUG_REPORT` or `ACCOUNT_ACCESS`?** If the failure is signing in, SSO or
  rejected credentials, it's account access, even if there's an error code.
- **`HOW_TO` or `FEATURE_REQUEST`?** "How do I…" or "Is there a way to…" is a
  question. "It would help if…" or "Please add…" is a request.
- **Mentions money but isn't about a charge?** "We'd pay for an add-on that…"
  is a `FEATURE_REQUEST`.

## When you're unsure

If a ticket raises two issues, route it by the first one. If it isn't a support
request at all, use **ignore**.
