# Is this issue about documentation?

You'll see one GitHub issue at a time: usually just the title, sometimes the title and the body. Decide whether the issue is about documentation.

- **Accept** if it is: it asks for docs, reports something wrong or missing in them, or proposes a change to them. Docs include docs pages, READMEs, guides, tutorials, API references, code examples and docstrings.
- **Reject** if it isn't: bugs, feature requests, questions and everything else.
- **Ignore** if you can't tell, e.g. the issue is empty, a test post or not in English.

## Telling the close ones apart

- **The docs are mentioned, but the issue is a bug.** "The docs say X should work, but it crashes" is about the code: reject. "The docs say X, but it actually does Y" is about the docs being wrong: accept.
- **Documentation tooling.** A bug in a docs generator or build plugin is a bug: reject, unless the issue is about the docs it produces.
- **Usage questions.** "How do I…?" on its own is a question: reject. "How do I…? It's not in the docs" asks for documentation: accept.

Go with your first reading of the title. If it takes long to decide, ignore the issue and move on: a few skipped examples don't matter, inconsistent answers do.
